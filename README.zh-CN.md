# 足球比赛录像个人复盘

[English](README.md) | 简体中文

这是一个面向 Codex 的足球比赛录像分析 Skill。只需提供比赛录像链接，以及能够识别目标球员的信息，它就能自动寻找球员的出场时间，按时间记录全部可可靠归属的进攻、防守、转换、定位球、有球和有明确战术意义的无球回合，分析可以改进的地方，并与之前的比赛表现进行比较。用户不需要预先总结比赛，也不需要自己标注时间点。

这个 Skill 以球员长期成长为目标，而不是只制作精彩集锦。它会区分录像中可以直接观察到的事实与战术推断，记录每项结论的时间点和可信度，并持续追踪球员在多场比赛中的进步与退步。

## 主要功能

- 首次使用时进行一次球员建档，了解年龄段、位置、身体特点、比赛赛制和强度、自觉问题及成长目标。
- 建立只保存在本地的长期球员档案，并在之后的复盘中理解球员的角色与诉求。
- 支持已知或未知的出场区间，并能统一处理不同格式的录像时间点。
- 在换人、中场换边、镜头切换或球衣变化后重新确认目标球员身份。
- 身份不清时同时保留多个可能人选，不强迫追踪器只选一条路径；每个机器候选都必须明确保留、合并、说明为何排除，或标为尚未解决。
- 连续复盘球员的全部出场时间，优先输出所有可辨认的个人相关回合；防守和无球动作不会因为没有触球而被省略。
- 所有用于人物相似度或追踪的身份参照都必须回到完整画面核对至少两个身份特征；一旦发现参照其实是队友，后续识别、候选排序和事件结论全部作废，用干净参照重跑完整出场时间。
- 将出场时间切成最长 30 秒的小段，分别完成球员身份追踪和动作分类；每段必须有明确去向，并记录相关回合或说明为什么该段确实没有相关动作。
- 候选片段和用户时间点只用于导航；盲扫时间线完成后，再逐条核对用户标记。
- 如果用户标记暴露了漏检，不只补这一条：记录漏检原因，并按同类动作回扫整场，例如漏掉一次争顶就重扫全部高空球。
- 另附完整接球子表，便于专项分析接球准备、第一脚与后场出球。
- 若使用抽帧代替直接播放，基线间隔不得超过 0.5 秒，疑似动作按不超过 0.25 秒复扫；接球、防守责任和第一动作后的后续处理必须各做一次全段专项回扫。
- 只有抽帧精度、三次专项复扫、原分辨率复核、候选去向和六项漏记复查全部写入并通过审计，才允许把账本称为“完整”。
- 如果球员指出旧报告持续漏记或跟错人，旧报告会被整体撤回，并从全部出场时间重建；不会只把用户说出的几个例子补进去。
- 用户提供的笔记和标记时间点属于可选补充，不是开始分析的前提。
- 分开评价决策质量、技术执行、战术效果和身体状态背景。
- 针对边后卫、中后卫、中场、边锋、前锋和门将使用不同的位置分析视角。
- 输出完整证据表、值得保留的优点、提升重点、三个比赛提示以及短期训练计划。
- 自动与历史基线比较：哪些方面进步了、哪些退步了、旧问题是否改善、哪些问题仍在重复，以及当前最值得优先提升的能力。

## 安装

将 Skill 目录复制到 Codex 的 skills 文件夹：

```bash
cp -R skills/analyze-football-match-video ~/.codex/skills/
```

也可以使用你常用的 Codex Skill 安装工具，从这个 GitHub 仓库安装。

## 首次建档

首次使用时，Skill 会集中询问一次球员资料，并在获得许可后创建私人档案。问题包括：

- 年龄或年龄段、惯用脚和踢球经历。
- 主要与次要位置、惯用侧以及教练布置的任务。
- 短距离启动、回追速度、耐力和对抗能力自评。
- 自己认为的优势、已发现的问题、当前最想提升的方面和长期目标。
- 比赛人数制、比赛水平、强度、时长、换人规则及球队打法。
- 可选的疼痛、伤病、疲劳或近期负荷背景。
- 是否允许在本地保存档案，以及是否允许每场复盘后自动更新。

你也可以通过附带的模板手动初始化私人档案：

```bash
python3 skills/analyze-football-match-video/scripts/init_player_profile.py
```

脚本会创建 `skills/analyze-football-match-video/references/player-profile.md`。该路径已被 Git 忽略，因此私人比赛链接、伤病信息、身份线索和历史发展档案不会被意外提交到公开仓库。

## 使用方式

首次建档完成后，通常只需要提供：

- 比赛录像链接或上传的视频文件。
- 球队颜色与球衣/背心号码，或者其他能够识别球员的线索。

出场区间、比赛时间点和赛后笔记都不是必填项。如果没有提供出场区间，Skill 会尝试从录像中自动寻找球员何时上场、离场、换边或改变位置。

## 输出内容

完整比赛复盘通常包含：

1. 分析范围、球员身份可信度和录像覆盖限制。
2. 覆盖审计：已复盘区块、身份丢失区间、被用户标记纠正后触发的同类全场复扫。
3. 本场表现的直接结论。
4. 全部可可靠归因的球员参与回合，包括进攻、防守、转换、定位球、触球和重要无球行动。
5. 所有确认接球的独立子集：编号、录像时间点、接球环境、第一脚处理、后续行动、结果和更优选择。
6. 值得继续保持的优点。
7. 与前几场相比的进步、退步和旧问题变化。
8. 当前最重要的提升点及一到两个次要重点。
9. 三个能够在比赛中直接记住的提示。
10. 带有衡量标准的短期训练计划。

如果长时间、清晰可见的出场区间只得到极少事件，Skill 会触发“漏记复查”，重新检查身份、攻防方向、全部来球/接球、无触球防守和第二动作。它不会设定最低事件数，也不会为了凑数量编造边缘片段。

如果录像不完整、镜头没有拍到接球前过程，或者无法确认球员身份，报告会明确标注“看不到”或“无法判断”，不会把未知内容写成确定结论。

覆盖审计能阻止系统把稀疏截图或候选高光误称为完整分析，但它不承诺机器级零漏检；身份丢失和不可见区间仍会作为报告限制明确列出。

## 示例请求

- “使用 `$analyze-football-match-video` 帮我复盘这场比赛。这是 Veo 链接，我是蓝队 10 号。”
- “把我所有接球都按时间点列出来，告诉我哪些回合可以处理得更好。我没有自己整理时间点。”
- “所有与我有关的防守回合都要记录，即使我没有触球。”
- “和之前几场比较一下：这场有哪些进步或退步？之前的问题有没有改善？”
- “我不知道具体什么时候上场，你根据白队 7 号和左后卫的位置帮我识别。”

## 隐私与限制

- 只分析用户有权访问的录像。
- 不擅自修改分享权限、上传或转发比赛录像。
- 不公开私人链接、登录信息、球员档案或不必要的身份信息。
- 身体疼痛和伤病信息只作为比赛背景，不根据录像进行医学诊断。
- 用户可以拒绝保存档案，也可以要求停止更新、更正或删除本地档案。

完整的证据、隐私和安全规则位于 Skill 的 `references` 目录中。
